## 函数的基本概念：从加运算说起

在数学上，我们已经习惯书写 $1 + 2 + 3 + \cdots + 100$ 这种表达式。尽管看起来非常普通，但这个表达式里其实已经包含了非常多函数式编程的重要思想。

### 函数定义

好吧，你可能会说，这里面哪有函数呢？其实 $+$ 就是一个二元函数，可以等价为 $\operatorname{add}$

$$
x + y = \operatorname{add}(x, y)
$$

$\operatorname{add}$ 输入两个实数，输出一个实数。我们可以用符号表示为

$$
\operatorname{add}: (\mathbb{R},\mathbb{R}) \to \mathbb{R}
$$

在 Javascript 里可以这样定义

```js
function add(x, y) {
  return x + y;
}
```

或者使用箭头函数

```js
const add = (x, y) => x + y;
```

有了 `add` 后，就可以改写原来的表达式。为了更可读，我们对代码进行缩进

```js
add(
  1,
  add(
    2,
    add(
      3,
      // ...
    ),
  ),
);
```

可以看到，虽然表达式变得更加复杂，但计算结果是一样的。

不过，这里其中有一些细微的差异：计算顺序不相同。$+$ 通常默认为左结合，即从左到右，从 $1$ 到 $100$；而我们的函数表达式其实是从右到左，从 $100$ 到 $1$。

### 函数的类型

$+$、$-$（减运算）、$\times$、$\div$ 都是二元函数，即接受两个参数并返回一个值。它们可以统一表示为

$$
f: (\mathbb{R},\mathbb{R}) \to \mathbb{R}
$$

这里需要区分几个概念

- 声明定义域：函数声明的输入集合
- 实际定义域：函数实际能够接受的输入集合
- 陪域：函数声明的输出集合
- 值域：函数实际能够取到的输出集合

在数学上通常不区分声明定义域和实际定义域，而只说定义域——此时指的其实是实际定义域；而值域在数学中也比陪域更加常见。

但函数式编程里，更常用的是声明定义域和陪域，函数实际的输入集合与输出集合通常较少关心。

上面的函数中，除 $\div$ 外声明的集合都和实际的集合相同；而 $\div$ 的第二个操作数是除数，不能为 $0$，所以它的实际定义域是，$(\mathbb{R},\mathbb{R}^*)$。其中 $\mathbb{R}^*$ 表示 $\mathbb{R}$ 除去 $\{0\}$ 中元素的差集，即 $\mathbb{R}^*=\mathbb{R} \setminus \{0\}$。

而 $-$（取负运算）、$\sin$、$\cos$、$\log$（底数为自然对数）、$\exp$（底数为自然对数）都是一元函数，可以表示为

$$
f: \mathbb{R} \to \mathbb{R}
$$

这里声明的集合与实际的集合之间也存在区别

- $\log$ 只能作用在正实数上，因此实际的输入集合是 $\mathbb{R^+}$
- $\exp$ 的结果只可能为正实数，因此实际的输出集合是 $\mathbb{R}^+$
- $\sin$ 和 $\cos$ 的结果绝对值不大于 $1$，因此实际的输出集合是 $[-1, 1]$

在实际编程中，我们会面对非常多的类型。

比如在 TypeScript 中就有 `number` / `string` / `boolean` / `null` / `undefined` 等基础类型，`T[]` / `[T1, T2]` / `{ p1: T1; p2: T2 }` / `T1 | T2` 等复合类型，以及直接把字面量作为类型的字面量类型。函数同样也有类型，它的类型由参数类型和返回值类型共同决定

```ts
function parseInteger(s: string) {
  return /^\d+$/.test(s) ? Number(s) : "请输入非负整数";
}
```

上述函数的类型就是 `string => number | "请输入非负整数"`，即参数类型为 `string`，值类型可能是 `number`，也可能是字面量 `"请输入非负整数"`。

函数类型的主要用处，就是推导函数之间能否组合，以及组合后会得到的函数会是什么类型。

### 函数的组合

现实世界中的函数是无穷无尽的，因为函数之间可以组合，而组合后可以得到一个新的函数。

不过我们先考虑纯数学中的例子。我们定义一个一元函数

$$
f(x) = \frac{x + 1}{x^2 - 1}
$$

使用 `add`、`sub`、`mul`、`div` 改写后能够更清晰地看出函数组合的本质

```js
function f(x) {
  return div(add(x, 1), sub(mul(x, x), 1));
}
```

其中 `mul` 的值被作为 `sub` 的参数，而 `add` 和 `sub` 的值又作为 `div` 的参数。这就引出了函数组合需要满足的要求：只有当上一个函数的输出可以作为下一个函数的输入时，这种组合才是可能的。

上述例子中，输出是可以匹配输入的

`div` 第二个参数实际只接受 $\mathbb{R}^*$，而这个位置是 `sub` 的返回值，因此 `sub` 的返回值被限制为 $\mathbb{R}^*$。但在不考虑 `div` 的情况下，`sub` 实际的输出集合是 $[-1, +\infty)$。这两个集合并不相同，在数学上，我们可以用差集判断那些输入非法，用交集判断那些输入合法

- 由于 $[-1, +\infty) \setminus \mathbb{R}^* = \{0\}$，因此 $\{0\}$ 不能用作 `div` 的输入或 `sub` 的输出
- 由于 $[-1, +\infty) \cap \mathbb{R}^*= [-1, 0] \cup (0, +\infty)$，因此 $[-1, 0] \cup (0, +\infty)$ 可以用作 `div` 的输入和 `sub` 的输出

经过一番推理后，我们最终可以确定这个函数实际的输入和输出集合为

$$
f: \mathbb{R} \setminus \{-1, 1\} \to \mathbb{R} \setminus \{ 0, -0.5 \}
$$

现在我们构造一个特殊的例子，看看当输出不匹配输入时会发生什么

$$
f(x)= \log(-\exp(x))
$$

1. $\exp$ 的实际输入和输出为 $\mathbb{R} \to \mathbb{R}^+$，因此 $\mathbb{R}$ 被映射到 $\mathbb{R}^+$
2. $-$ 的输入接上 $\exp$ 的输出 $\mathbb{R}^+$，而 $-$ 在 $\mathbb{R}^+$ 上的像集为 $\mathbb{R}^-$，因此 $\mathbb{R}^+$ 被映射到 $\mathbb{R}^-$
3. $\log$ 的输入接上 $-$ 的输出 $\mathbb{R}^-$，但 $\log$ 实际只接受 $\mathbb{R}^+$，而 $\mathbb{R}^+ \cap \mathbb{R}^- = \empty$，因此不存在合法的输入

最后我们发现，任何 $x \in \mathbb{R}$ 都无法作为 $f$ 的输入。因此在实数范围内，这种组合是失败的，我们没有得到新的函数。

在实际编程里，函数类型的推导与之类似。

只不过编程里的函数通常不会考虑实际接受的输入集合和实际，而只在声明的类型上进行推导。

有些语言，比如 TypeScript，可以根据函数的返回值和声明的参数类型，自动推导出返回值的类型；但这种类型推导显然不会像刚才的分析那么细致。编程里的函数通常不会去计算实际接受的输入集合和实际取到的输出集合，而只在声明的输入类型上进行类型层面的推导。

这是一个 TypeScript 中的例子

```ts
const getLength = (s: string): number => s.length;
const isBig = (n: number): boolean => n > 32;
```

这两个函数分别对应类型

$$
\begin{align*}
  \text{getLength} &: \text{string} \to \text{number} \\
  \text{isBig} &: \text{number} \to \text{boolean}
\end{align*}
$$

如果把 `getLength` 的返回值作为 `isBig` 的参数

```ts
const isLongString = (s: string) => isBig(getLength(s));
```

由于两者类型都是 `number`，因此可以进行组合，并且 TypeScript 能够推断出 `isLongString` 的类型应该为

$$
\text{isLongString}: \text{string} \to \text{boolean}
$$

但反过来把 `isBig` 的返回值作为 `getLength` 的参数就存在问题

```ts
const bad = (n: number) => getLength(isBig(n));
```

这里 `isBig` 的返回值是 `boolean` 而 `getLength` 的参数为 `string`，类型不匹配。因此无法这样组合。

### 函数的复合

函数复合是一种特殊的函数组合，通常用于一组输入和输出可以匹配的函数。

还是先在纯数学中举例。我们有这样一组一元函数

$$
\begin{align*}
  f: A \to B \\
  g: B \to C \\
  h: C \to D \\
\end{align*}
$$

我们希望先计算 $f$，再计算 $g$，最后计算 $h$，即

$$
A \xrightarrow{f} B \xrightarrow{g} C \xrightarrow{h} D
$$

那么这个组合出来的函数需要这样写

$$
h(g(f(x)))
$$

如果再多计算几个函数，这种嵌套会变得非常复杂，难以阅读。数学中用办法简化此时的函数组合，就是函数复合

$$
h \circ g \circ f: A \to D
$$

复合的顺序是从右到左。函数复合是直接对函数进行计算，得到的结果是一个新的函数。在这个函数上输入原来的参数，就可以得到之前组合后的结果

$$
(h \circ g \circ f)(x) = h(g(f(x)))
$$

有部分编程语言可以类似这样简化函数复合的写法。最常见的语法就是管道——几乎就是把函数复合换了个符号，只不过管道的顺序是从左到右，而函数复合是从右到左

$$
h \circ g \circ f \Leftrightarrow f \mid g \mid h
$$

而最初送入管道的值，通常就放到管道的最左边

$$
x \mid f \mid g \mid h
$$

比如 Bash 的管道

```bash
cat server.log \
  | grep "ERROR" \
  | sort \
  | uniq -c
```

这可以被理解为

```js
uniq_count(sort(grep_error(cat("server.log"))));
```

每个函数（bash 中的术语是命令）的输入是文本，输出也是文本，因此每个函数都是

$$
\text{Text} \to \text{Text}
$$

这满足了函数复合的要求——前一个函数的输出匹配下一个函数的输入。而管道就是把前一个函数的输出作为下一个函数的输入，这就是一种更清晰的、减少函数嵌套的函数复合语法。

再比如 jq 的管道

```jq
.users[]
| select(.age >= 18)
| .name
```

jq 的每个函数都输入 JSON 对象，然后输出 JSON 对象

$$
\text{JSON} \to \text{JSON}
$$

甚至 SQL 也能支持管道语法，比如 GoogleSQL

```sql
FROM users
|> WHERE age >= 18
|> SELECT name, age
|> ORDER BY age DESC
|> LIMIT 10;
```

SQL 的每个函数（SQL 中的术语是操作）都接收表，然后返回表

$$
\text{Table} \to \text{Table}
$$

而在最纯粹的函数式语言 Haskell 里，函数复合的语法更是直接

```haskell
sumSquaresOfEvens :: [Int] -> Int
sumSquaresOfEvens = sum . map (^2) . filter even
```

Haskwll 的函数复合是从右到左而非从左到右，完全照搬数学上的写法，连符号都很相似

$$
\text{sum} \circ \text{map(square)} \circ \text{filter(even)}
$$

这些函数的类型分别为

```haskell
filter even :: [Int] -> [Int]
map (^2)    :: [Int] -> [Int]
sum         :: [Int] -> Int
```

因此，复合时的情况是

$$
[Int] \to [Int] \to [Int] \to Int
$$

所以这些函数可以把输入输出连接起来，复合成一个函数。

JavaScript 目前还没有原生的管道语法，不过可以自己手动实现一个简易的 `pipe`

```js
export function pipe(...fns) {
  return (value) => fns.reduce((value, fn) => fn(value), value);
}
```

这里 `pipe` 本身是一个函数，它的参数是函数，返回值也是函数。这叫做高阶函数——我们马上就会讲到。

`pipe` 返回的函数只有一个参数 `value`。`pipe` 会首先把自身参数中的第一个函数作用在这个 `value` 上，得到的值会被第二个函数作用，然后新的值再被第三个函数作用，一直重复直到最后一个函数作用完成。

`reduce` 会在后续详细介绍。这里只需要知道，`reduce` 有两个参数：第二个参数是初始值，第一个参数是函数。而这个函数的第一个参数是上次计算的结果（未计算时就是初始值），第二个参数是调用 `reduce` 的数组中的一个元素。

## 高阶函数：函数族、泛函与算子

我猜你应该在尝试弄懂 `reduce` 各参数的含义时被绕晕了。坏消息是，我们已经介绍完了函数的基本概念，后续的内容都将开始变得抽象。而好消息是，如果逐渐地深入，那么理解这些概念其实并不困难。

接下来要介绍的就是函数式编程中相对抽象，但非常重要的概念——高阶函数。

高阶函数指的是参数或返回值中含有函数的函数。为了建立数学直觉，我们先通过三类常见的数学对象——函数族、泛函和算子——来理解高阶函数。

### 函数族

函数族的输入是数，输出是函数。

在数学上，典型的函数族就是对数函数族

$$
\operatorname{Log}: a \mapsto \log_a
$$

其类型为

$$
\operatorname{Log}: \mathbb{R}^+ \setminus \{1\} \to (\mathbb{R}^+ \to \mathbb{R})
$$

对数函数族接受一个底数，然后返回一个对数函数。

所有对数函数都可以通过 $\operatorname{Log}$ 函数族生成出来。而对于那些常用的对数函数，数学中都有别名

$$
\begin{align*}
  \operatorname{Log}(e) &= \log_e = \ln \\
  \operatorname{Log}(10) &= \log_{10} = \lg
\end{align*}
$$

对返回的函数进行调用就能得到值，这可以等价为对原来的函数族调用两次

$$
\log_a x = \operatorname{Log}(a)(x)
$$

虽然后一种写法在数学上不太常见，但在函数式编程里却非常重要。后面提到的柯里化就和函数族密切相关。

指数函数族也可以这样表示，通过接受底数，返回一个指数函数

$$
\operatorname{Exp}: a \mapsto a^x
$$

类型可以表示为

$$
\operatorname{Exp}: \mathbb{R}^+ \setminus \{1\} \to (\mathbb{R} \to \mathbb{R}^+)
$$

在 JavaScript 里可以如下定义函数族

```js
const Log = (a) => (x) => Math.log(x) / Math.log(a);
```

然后通过这个函数族生成一连串函数并调用

```js
const ln = Log(Math.E);
const lg = Log(10);

lg(1000);
Log(10)(1000);
```

也展示一下 Haskell 的写法

```haskell
logFamily :: Floating a => a -> a -> a
logFamily a x = log x / log a

ln = logFamily (exp 1)
log10 = logFamily 10

log10 1000
logFamily 10 1000
```

当然对于 Haskell，标准库里其实已经有了对数函数族 `logBase`，直接用就行

```haskell
log10 = logBase 10
log10 1000
logBase 10 1000
```

### 泛函

泛函的输入是函数，输出是数。

在数学上，典型的泛函就是定积分

$$
\int_{a}^{b}: f \mapsto F(b) - F(a)
$$

不考虑积分区间和可积性等问题，其类型为

$$
\int_{a}^b: (\mathbb{R} \to \mathbb{R}) \to \mathbb{R}
$$

一个定区间积分泛函的示例如下

$$
I_0^1(f) = \int_0^1 f(x) \mathrm{d}x
$$

把这个泛函作用于函数，就能得到其在 $[0, 1]$ 区间上的积分

$$
I_0^1(2x) = \int_0^1 2x \mathrm{d}x = 1
$$

Haskell 的标准库里没有积分，我们先实现一个简单的数值积分

```haskell
integrate :: Double -> Double -> (Double -> Double) -> Double
integrate a b f =
  let n  = 10000
      dx = (b - a) / fromIntegral n
  in sum [f (a + (fromIntegral i + 0.5) * dx) * dx | i <- [0 .. n - 1]]
```

然后可以这样表示定区间 $[0, 1]$ 上的积分泛函

```haskell
integralFrom0To1 :: (Double -> Double) -> Double
integralFrom0To1 f = integrate 0 1 f
```

最后给这泛函一个函数，就会返回其在 $[0, 1]$ 上定积分的结果。由于数值积分的精度问题，结果不完全准确

```haskell
ghci> integralFrom0To1 (\x -> 2 * x)
0.9999999999999998
ghci> integralFrom0To1 sin
0.45969769432340096
ghci> integralFrom0To1 cos
0.8414709851585067
```

### 算子

算子的输入和输出都是函数。

在数学上，典型的算子就是求导

$$
D: f \mapsto f'
$$

同样不考虑可微性，其类型为

$$
\mathcal{D}: (\mathbb{R} \to \mathbb{R}) \to (\mathbb{R} \to \mathbb{R})
$$

求导算子接受一个函数，然后返回其导函数，比如

$$
\mathcal{D}: x^2 \mapsto 2x
$$

变限积分也是一个算子，这是一种上限或下限不固定的积分。比如变上限积分

$$
\int_a^x: f \mapsto F(x) - F(a)
$$

在不考虑可积性时，其类型也是

$$
\int_a^x: (\mathbb{R} \to \mathbb{R}) \to (\mathbb{R} \to \mathbb{R})
$$

变限积分接受一个函数，返回其原函数。比如

$$
\int_{0}^{x}: 2x \mapsto x^2
$$

在 Haskell 的标准库里没有微分，我们先定义一个简单的数值微分

```haskell
derivative :: (Double -> Double) -> (Double -> Double)
derivative f = \x ->
    let h = 1e-6
    in (f (x + h) - f (x - h)) / (2 * h)
```

然后对 $x^2$ 运用求导算子

```haskell
square' = derivative (\x -> x * x)
```

得到的就是其导函数 $2x$。不过由于数值微分的精度问题，不完全准确

```haskell
ghci> square' 2
4.000000000115023
ghci> square' 3
6.000000000838668
ghci> square' 4
8.000000000230045
ghci> square' 5
10.00000000139778
```

对于变上限积分也一样。还是使用之前编写的数值积分

```haskell
integrate :: Double -> Double -> (Double -> Double) -> Double
integrate a b f =
  let n  = 10000
      dx = (b - a) / fromIntegral n
  in sum [f (a + (fromIntegral i + 0.5) * dx) * dx | i <- [0 .. n - 1]]
```

这里第一个参数是下限，第二个参数是上限，第三个参数是函数。我们要交换一下变量顺序，让下限的后一个参数是函数

```haskell
integralFromLower :: Double -> (Double -> Double) -> (Double -> Double)
integralFromLower a f x = integrate a x f
```

这部分内容在柯里化部分会详细介绍。现在我们就得到了变上限积分算子

```haskell
integralFromLower0 :: (Double -> Double) -> (Double -> Double)
integralFromLower0 = integralFromLower 0
```

然后对 $2x$ 运用变上限积分算子

```haskell
square = integralFromLower0 (\x -> 2 * x)
```

得到的函数就是 $x^2$。不过由于数值积分的精度问题，不完全准确

```haskell
ghci> square 2
3.999999999999999
ghci> square 3
9.0
ghci> square 4
15.999999999999996
ghci> square 5
25.0
```

### 一般高阶函数

前面提到的只是数学上比较典型的高阶函数，而一般的高阶函数本身可以更加复杂。

比如，不定积分就是一个比函数族、泛函和算子更复杂的高阶函数。

在数学上，不定积分接受一个函数，然后返回其原函数族

$$
\int: f \mapsto F_C
$$

其中 $F_C$ 更常见的写法是 $F(x)+C$，但这里我们明确将 $C$ 看作一个参数，只有指定了这个参数，才能确定函数族中的一个函数。因此 $F_C$ 就是之前提到的、被参数化的函数族，其类型为 $\mathbb{R} \to (\mathbb{R} \to \mathbb{R})$。

于是，不考虑可积性时，不定积分的类型为

$$
\int: (\mathbb{R} \to \mathbb{R}) \to (\mathbb{R} \to (\mathbb{R} \to \mathbb{R}))
$$

比如

$$
\int: 2x \mapsto x^2 + C
$$

在指定 $C$ 后就能确定唯一的原函数。

对于代码示例，我们沿用之前在 Haskell 里实现的简单数值积分

```haskell
integrate :: Double -> Double -> (Double -> Double) -> Double
integrate a b f =
  let n  = 10000
      dx = (b - a) / fromIntegral n
  in sum [f (a + (fromIntegral i + 0.5) * dx) * dx | i <- [0 .. n - 1]]
```

这里第一个参数是下限，第二个参数是上限，第三个参数是函数。我们需要修改一下参数顺序

```haskell
integralIndefinite :: (Double -> Double) -> Double -> Double -> Double
integralIndefinite f c x = integrate 0 x f + c
```

上述代码会在后续解释。这里我们先测试几个示例

```haskell
ghci> cosF = integralIndefinite cos 0
ghci> cosF 0
0.0
ghci> cosF 1
0.8414709851585067
ghci> cosF 2
0.9092974283411775
ghci> cosF pi
1.0728180496744066e-16
ghci> cosF (pi/2)
1.0000000010280823
```

## 柯里化和部分应用

### 柯里化：对数函数、指数函数和四则运算

此前已经提到了对数函数族。对于这样一个表达式

$$
\log_a x
$$

显然我们需要同时知道 $a$ 和 $x$ 的值，才能得知结果。因此，对数运算其实是一个二元函数

$$
\operatorname{Log}(a, x) = \log_a x
$$

我们把参数 $(\mathbb{R}, \mathbb{R})$ 改写成笛卡尔积的形式 $\mathbb{R} \times \mathbb{R}$，于是 $\operatorname{Log}$ 的类型为

$$
\operatorname{Log}: \mathbb{R} \times \mathbb{R} \to \mathbb{R}
$$

但此前介绍函数族的时候，我们已经发现：我们通常都会固定底数，得到那些常用的对数函数

$$
\operatorname{Log}(e) = \log_e = \ln
$$

在这里 $\operatorname{Log}$ 接受一个参数，然后返回一个函数，其类型为

$$
\operatorname{Log}: \mathbb{R} \to (\mathbb{R} \to \mathbb{R})
$$

这和我们最开始看到的类型 $\mathbb{R} \times \mathbb{R} \to \mathbb{R}$ 不一样，但显然，这里的 $\operatorname{Log}$ 仍然表示对数运算！因此我们可知这两种类型是同构的

$$
(\mathbb{R} \times \mathbb{R} \to \mathbb{R}) \cong (\mathbb{R} \to (\mathbb{R} \to \mathbb{R}))
$$

现在，我们可以先固定底数得到一个常用的对数函数，然后再对这个常用对数函数指定参数得到最终的结果；或者也可以进行多次调用，直接得到结果

$$
\operatorname{Log}(2)(8) = \log_2 8
$$

也就是说，原先的二元函数 $\operatorname{Log}$，现在变成了一连串一元函数。

这就是 **柯里化**：把多元函数等价转化为一连串的一元函数。

指数函数也是类似的。对于如下表达式

$$
a^x
$$

需要同时知道 $a$ 和 $x$ 的值才能计算出结果。因此指数运算是二元函数

$$
\operatorname{Exp}(a, x) = a^x
$$

但通过柯里化，我们可以先固定底数，得到那些常见的指数函数

$$
\operatorname{Exp}(e) = e^x = \exp
$$

柯里化让函数的类型发生改变

$$
\begin{align*}
  \operatorname{Exp} &: \mathbb{R} \times \mathbb{R} \to \mathbb{R} \\
  \operatorname{Exp} &: \mathbb{R} \to (\mathbb{R} \to \mathbb{R}))
\end{align*}
$$

但运算本身仍然是相同的。

四则运算这些二元函数也全都可以柯里化。就以加法为例。

首先加法通常被认为是一个二元函数

$$
\operatorname{add}: \mathbb{R} \times \mathbb{R} \to \mathbb{R}
$$

但通过柯里化，加法被转换为一连串一元函数

$$
\operatorname{add}: \mathbb{R} \to (\mathbb{R} \to \mathbb{R})
$$

用 JavaScript 表示就是

```js
// 未柯里化
const add = (x, y) => x + y;

// 柯里化
const add = (x) => (y) => x + y;
```

然后我们就可以一次只传一个参数，或者通过多次调用的方式一次传多个参数

```js
const add5 = add(5);
add5(3);

add(5)(3);
```

对于一般的二元函数

$$
f: A \times B \to C
$$

可以被柯里化为

$$
\operatorname{curry}(f): A \to (B \to C)
$$

也可以把已经柯里化的函数

$$
g: A \to (B \to C)
$$

反柯里化为

$$
\operatorname{uncurry}(g): A \times B \to C
$$

用集合论解释就是，从 $A \times B$ 映射到 $C$ 的所有函数组成的函数空间，与从 $A$ 映射到 $\operatorname{Hom}(B, C)=\{f\mid f: B \to C\}$ 的所有函数组成的函数空间同构

$$
\operatorname{Hom}(A \times B, C)
\cong
\operatorname{Hom}(A, \operatorname{Hom}(B, C))
$$

而在范畴论黑话里，这通常表述为：在笛卡尔闭范畴 $\mathcal C$ 上，对每个对象 $B$，积函子

$$
(-\times B):\mathcal C\to\mathcal C \qquad A\mapsto A\times B
$$

是幂函子

$$
(-)^B:\mathcal C\to\mathcal C \qquad C\mapsto C^B
$$

的左伴随

$$
(-\times B)\dashv (-)^B
$$

更一般地，任意一个多元函数

$$
f: A_1 \times A_2 \times \cdots \ A_n \to B
$$

都可以被柯里化为一连串一元函数

$$
f: A_1 \to A_2 \to \cdots \to A_n \to B
$$

### 部分应用：不定积分、变限积分和定积分

部分应用和柯里化密切相关。在柯里化章节里已经提到了部分应用，其意思是：先对函数应用部分参数，得到一个部分应用的函数。以自然对数为底的对数函数就是一个典型的例子

$$
\operatorname{Log}(e) = \log_e = \ln
$$

我们先固定了底数，此后使用 $\ln$ 时就不需要再指定底数了。

我们现在看另一个部分应用的例子。

回顾我们之前定义的数值积分

```haskell
integrate :: Double -> Double -> (Double -> Double) -> Double
integrate a b f =
  let n  = 10000
      dx = (b - a) / fromIntegral n
  in sum [f (a + (fromIntegral i + 0.5) * dx) * dx | i <- [0 .. n - 1]]
```

具体的数值算法并不重要，这里需要关注的点是：我们把积分运算定义为一个三元函数，其中第一个参数是下限，第二个参数是上限，第三个参数是被积函数，返回值是定积分的结果

$$
I(a,b,f)=\int_a^b f
$$

我们用 $C(\mathbb{R})$ 表示函数，那么其类型为

$$
I: \mathbb{R} \times \mathbb{R} \times C(\mathbb{R}) \to \mathbb{R}
$$

Haskell 的函数会自动柯里化。所以其类型等价为

$$
I: \mathbb{R} \to \mathbb{R} \to C(\mathbb{R}) \to \mathbb{R}
$$

回顾一下我们之前如何在 Haskell 里定义定积分

```haskell
-- 区间 [0,1] 上的定积分
integralFrom0To1 :: (Double -> Double) -> Double
integralFrom0To1 = integrate 0 1
```

我们发现一件有趣的事情：定积分固定了 $I$ 的前两个参数，即上下限，从而得到了在指定区间上的定积分

$$
\int_a^b = I(a,b)
$$

因此，虽然 $I$ 是一个三元函数，但我们并不一定要为每个参数都进行赋值才能得到结果。我们可以只应用部分参数，得到一个部分应用的函数；然后这个部分应用的函数后续可以再接受剩余的参数。

这就是 **部分应用**：在一个函数上先固定一部分参数，然后返回一个接受剩余参数的新函数。

同样的，对于变上限积分或者变下限积分，我们也可以这样做

```haskell
-- 下限为 0 的变上限积分
integralFromLower :: (Double -> Double) -> (Double -> Double)
integralFromLower f x = integrate 0 x f

-- 上限为 1 的变下限积分
integralToUpper :: (Double -> Double) -> (Double -> Double)
integralToUpper f x = integrate x 1 f
```

- 变上限积分先固定第一个参数，即下限，然后交换了剩余两个参数的位置，从而让变上限积分的第一个参数是函数
- 变下限积分则是先固定第二个参数，即上限，然后也按照需要交换了剩余参数的位置。

这也是部分应用。部分应用不一定要按着顺序应用参数，并且还可以在部分应用时调整返回函数的参数顺序。

最后对于不定积分，我们也可以通过部分应用进行定义

```haskell
integralIndefinite :: (Double -> Double) -> Double -> Double -> Double
integralIndefinite f c x = integrate 0 x f + c
```

这里我们指定了下限为 $0$。这个下限是随便选的，因为变上限积分公式允许下限是一个任意常数

$$
F(x) = \int_a^x f + C
$$

而不定积分就是变上限积分得到的原函数加上积分常数 $C$。

就这样，我们把一个三元积分运算，通过部分应用而分别得到了不定积分、变限积分和定积分多种运算。

### 柯里化与部分应用的编程优势

好吧，虽然柯里化在数学上有非常优美的形式，但在编程里把函数柯里化，有什么好处呢？

显然，一个最直观的用途就是——让多元函数可以进入单参数的管道。

多元函数需要多个参数，因此在单参数的管道里，多元函数没办法把自己的输入接到任何函数的输出上。而柯里化可以把多元函数转变为一连串的一元函数，从而能够进入管道。

回顾之前提到的 Bash 管道示例

```bash
cat server.log \
  | grep "ERROR" \
  | sort \
  | uniq -c
```

在函数式的视角，我们可以认为 `grep` 其实是一个二元函数：第一个参数是模式字符串，第二个参数是待匹配的文本。而我们指定了第一个参数后，得到了一个一元函数，这个函数只需输入待匹配的文本，而文本现在就可以通过管道传进来。

柯里化的另一个好处就是参数复用。通过提前固定一部分参数，得到一个更具体的函数，后续只需使用这个更具体的函数即可，不需要重复传参。而且，即使得到具体函数时使用的参数名称改了，后面的代码通常也不需要修改——只要函数名的语义仍然正确

```js
const log = (app) => (level) => (message) => {
  console.log(`[${app}] [${level}] ${message}`);
};

const myAppLog = log("MyAppName");

const info = myAppLog("INFO");
const error = myAppLog("ERROR");

info("Server started");
error("Database failed");
```

再一个优势就是代码更加声明式，只看函数名就能知道函数有什么用，而不用考虑每个位置的参数是什么意思

```js
const applyDiscount = (rate) => (price) => price * (1 - rate);
const vipDiscount = applyDiscount(0.2);

const prices = [100, 200, 300];
prices.map(vipDiscount);
```

## 5. `map` 与 Functor

JavaScript：

```js
xs.map(f);
```

只是 API 设计成了 method：

```text
Array object → .map(...)
```

它与 JavaScript 的：

```js
new Map();
```

毫无理论关系。

`Map` 是键值容器；`Array.prototype.map` 中的 `map` 才对应函数式编程中的 mapping。

完全可以把它改写成独立函数：

```js
const map = (f) => (xs) => xs.map(f);
```

于是：

```js
map(f)(xs);
```

更接近数学表示。

## 6. Functor 的数学定义

给定两个范畴：

$$
\mathcal C,\mathcal D
$$

一个函子：

$$
F:\mathcal C\to\mathcal D
$$

包含两部分。

### 对对象的映射

$$
A\mapsto F(A)
$$

### 对态射的映射

若：

$$
f:A\to B
$$

则：

$$
F(f):F(A)\to F(B)
$$

并且必须满足两个定律。

### 保持恒等态射

$$
F(\operatorname{id}_A) = \operatorname{id}_{F(A)}
$$

### 保持复合

$$
F(g\circ f) = F(g)\circ F(f)
$$

---

### List / Array 作为例子

对象：

$$
A\mapsto List(A)
$$

函数：

$$
f:A\to B
$$

被提升成：

$$
List(f):List(A)\to List(B)
$$

其中：

$$
List(f)([a_1,\ldots,a_n]) = [f(a_1),\ldots,f(a_n)]
$$

JavaScript 中就是：

```js
xs.map(f);
```

因此 `map` 的核心作用可以概括为：

$$
(A\to B)
\longmapsto
(F(A)\to F(B))
$$

同时保持恒等与复合。

## 7. `reduce` 比 Monoid 更一般

JavaScript：

```js
xs.reduce(f, initial);
```

并不要求 `initial` 是单位元。

一般来说：

$$
\operatorname{foldl}:
(A\times B\to A)
\to
A
\to
List(B)
\to
A
$$

也就是：

- $A$：累积器类型
- $B$：元素类型
- $A\times B\to A$：每一步如何更新累积器
- 初始值只需要属于 $A$

例如：

```js
users.reduce(
  (acc, user) => ({
    ...acc,
    [user.id]: user,
  }),
  {},
);
```

这并不是简单的幺半群折叠。

### Monoid 只是一个特殊情况

如果：

$$
(A,\star,e)
$$

满足：

$$
(a\star b)\star c = a\star(b\star c)
$$

且：

$$
e\star a=a\star e=a
$$

那么可以：

$$
\operatorname{reduce}(\star,e)
$$

例如求和：

$$
(\mathbb Z,+,0)
$$

所以：

> Monoid 能自然地产生一种 `reduce`，但 `reduce` 本身不要求 Monoid。

## 8. Option / Result：扩展陪域

若：

$$
f:A\rightharpoonup B
$$

只是一个部分函数，例如：

$$
f(x)=\frac1x
$$

在 $x=0$ 时没有定义。

可以把它改成 total function：

$$
\hat f:A\to B\cup\{\mathrm{Failure}\}
$$

前提是：

$$
\mathrm{Failure}\notin B
$$

更严格地，为避免元素碰撞，常写成不交并：

$$
B\sqcup\{\mathrm{Failure}\}
$$

或者类型论中常写：

$$
B+E
$$

这里的 $+$ 不是普通数值加法，而是 **coproduct / sum type**。

程序中：

```text
Option<B>
Result<B, E>
```

正是在做这件事。

## 9. Monad 与错误传播

假设：

$$
f:A\to Result(B,E)
$$

$$
g:B\to Result(C,E)
$$

普通复合：

$$
g\circ f
$$

无法成立，因为 $f$ 的输出不是 $B$。

Monad 提供一种组合操作，通常称为：

$$
\operatorname{bind}
$$

类型：

$$
Result(A,E)
\to
(A\to Result(B,E))
\to
Result(B,E)
$$

于是：

$$
A\to Result(B,E)
$$

与：

$$
B\to Result(C,E)
$$

可以进行 Kleisli composition：

$$
g\star f:
A\to Result(C,E)
$$

---

### 不会产生“error drilling”吗？

如果手写：

```js
const r = f(x);

if (!r.ok) return r;

return g(r.value);
```

确实会产生大量样板代码。

因此实际函数式 API 会把这段逻辑封装进：

```js
result.flatMap(g);
```

或：

```js
bind(result, g);
```

从而写成：

```js
parse(input).flatMap(validate).flatMap(calculate).flatMap(format);
```

错误传播由 `flatMap/bind` 自动处理。

不同语言进一步提供语法糖：

```text
Haskell        do notation
Scala          for-comprehension
Rust           ?
Elixir         with
JavaScript     Promise.then / async-await
```

所以 Monad 的意义之一正是：

> 把“传播上下文”的样板逻辑从每个业务函数中抽离出来。

## 10. 递归与不动点

不能直接写：

$$
F(n)=nF(n-1)
$$

来解释“不动点”，因为这里的 $F$ 已经是最终递归函数本身。

要讨论不动点，必须再高一阶。

定义一个**作用于函数的算子**：

$$
\Phi:(\mathbb N\to\mathbb N)
\to
(\mathbb N\to\mathbb N)
$$

定义：

$$
\Phi(g)(n) =
\begin{cases}
1,&n=0\\
n\,g(n-1),&n>0
\end{cases}
$$

注意：

- $g$ 是输入函数；
- $\Phi(g)$ 是输出函数；
- 此时没有递归调用 $\Phi$。

现在寻找一个函数 $f$，满足：

$$
\Phi(f)=f
$$

这样的 $f$ 就是 $\Phi$ 的不动点。

代入：

$$
f(n) =
\begin{cases}
1 & n = 0 \\
nf(n-1) & n>0
\end{cases}
$$

于是：

$$
f(n)=n!
$$

因此 factorial 可以理解为：

$$
\boxed{f=\operatorname{fix}(\Phi)}
$$

其中 fixed-point operator 满足：

$$
\operatorname{fix}(\Phi) = \Phi(\operatorname{fix}(\Phi))
$$

Lambda Calculus 中的 $Y$ combinator 就满足类似关系：

$$
Y(\Phi)=\Phi(Y(\Phi))
$$

关键区别：

$$
\Phi
$$

是“函数 → 函数”的高阶算子；

$$
f
$$

才是真正的递归函数。

## 总体对应

| 函数式编程            | 数学结构                            |
| --------------------- | ----------------------------------- |
| pure function         | 映射 $A\to B$                       |
| higher-order function | 函数空间上的映射                    |
| operator              | 函数 $\to$ 函数                     |
| functional            | 函数 $\to$ 标量                     |
| closure               | $A\to(B\to C)$ / 参数化函数族       |
| currying              | $A\times B\to C \cong A\to(B\to C)$ |
| composition / pipe    | 函数复合                            |
| map                   | 函子的态射映射                      |
| Functor               | 保持恒等与复合的范畴间映射          |
| reduce / fold         | 代数上的折叠                        |
| monoid reduction      | fold 的重要特殊情况                 |
| Option / Result       | 扩展陪域 / sum type                 |
| bind / flatMap        | Kleisli composition                 |
| recursion             | 高阶算子的不动点                    |

函数式编程最值得把握的一条主线是：

$$
\boxed{
\text{值}
\rightarrow
\text{函数}
\rightarrow
\text{函数之间的组合}
\rightarrow
\text{保持组合的结构}
}
$$

所以 FP 最深层的魅力并不只是“函数是一等公民”，而是：

$$
\boxed{\text{程序逐渐变成一个可以用代数规律推理的对象}}
$$

这也是它与数学之间最根本的联系。

## 函数的基本概念：从加运算说起

在数学上，我们已经习惯书写 $1 + 2 + 3 + \cdots + 100$ 这种表达式。尽管看起来非常普通，但这个表达式里其实已经包含了非常多函数式编程的重要思想。

### 函数定义

好吧，你可能会说，这里面哪有函数呢？其实 $+$ 就是一个二元函数，可以等价为 $\operatorname{add}$

$$
x + y = \operatorname{add}(x, y)
$$

$\operatorname{add}$ 输入两个实数，输出一个实数。我们可以用符号表示为

$$
\operatorname{add}: (\mathbb{R},\mathbb{R}) \to \mathbb{R}
$$

在 Javascript 里可以这样定义

```js
function add(x, y) {
  return x + y;
}
```

或者使用箭头函数

```js
const add = (x, y) => x + y;
```

有了 `add` 后，就可以改写原来的表达式。为了更可读，我们对代码进行缩进

```js
add(
  1,
  add(
    2,
    add(
      3,
      // ...
    ),
  ),
);
```

可以看到，虽然表达式变得更加复杂，但计算结果是一样的。

不过，这里其中有一些细微的差异：计算顺序不相同。$+$ 通常默认为左结合，即从左到右，从 $1$ 到 $100$；而我们的函数表达式其实是从右到左，从 $100$ 到 $1$。

### 函数的类型

$+$、$-$（减运算）、$\times$、$\div$ 都是二元函数，即接受两个参数并返回一个值。它们可以统一表示为

$$
f: (\mathbb{R},\mathbb{R}) \to \mathbb{R}
$$

不过 $\div$ 的第二个操作数不能为 $0$，所以它更准确的表示为 $f: (\mathbb{R},\mathbb{R}^*) \to \mathbb{R}$。

而 $-$（取负运算）、$\sin$、$\cos$、$\log$（底数为自然对数）、$\exp$（底数为自然对数）都是一元函数，可以表示为

$$
f: \mathbb{R} \to \mathbb{R}
$$

同样的，$\log$ 只能作用在正实数上，因此更准确的表示为 $f: \mathbb{R^+} \to \mathbb{R}$；$\exp$ 的结果只可能为正实数，所以更准确的表示为 $f: \mathbb{R} \to \mathbb{R}^+$。

这种表示其实就可以作为函数的类型。

在实际编程中，我们会面对非常多的类型。比如在 TypeScript 中就有 `number` / `string` / `boolean` / `null` / `undefined` 等基础类型，`T[]` / `[T1, T2]` / `{ p1: T1; p2: T2 }` / `T1 | T2` 等复合类型，以及直接把字面量作为类型的字面量类型。函数同样也有类型，它的类型由参数类型和返回值类型共同决定

```ts
function parseInteger(s: string) {
  return /^\d+$/.test(s) ? Number(s) : "请输入非负整数";
}
```

上述函数的类型就是 `string => number | "请输入非负整数"`，即参数类型为 `string`，值类型可能是 `number`，也可能是字面量 `"请输入非负整数"`。

函数类型的主要用处，就是推导函数之间能否组合，以及组合后会得到的函数会是什么类型。

### 函数的组合

现实世界中的函数是无穷无尽的，因为函数之间可以组合，而组合后可以得到一个新的函数。

不过我们先考虑纯数学中的例子。我们定义一个一元函数

$$
f(x) = \frac{x + 1}{x^2 - 1}
$$

使用 `add`、`sub`、`mul`、`div` 改写后能够更清晰地看出函数组合的本质

```js
function f(x) {
  return div(add(x, 1), sub(mul(x, x), 1));
}
```

其中 `mul` 的值被作为 `sub` 的参数，而 `add` 和 `sub` 的值又作为 `div` 的参数。这就引出了函数组合需要满足的要求：只有当上一个函数的输出可以作为下一个函数的输入时，这种组合才是可能的。

上述例子中，输出是可以匹配输入的。`div` 的第二个参数是 $\mathbb{R}^*$，值是 `sub` 的值，而 `sub` 可能返回的值的范围是 $[-1, +\infty)$，而 `div` 第二个参数的。由于 $[-1, +\infty) \setminus \mathbb{R}^* = \{0\}$ 不为空集，因此存在不能用作输入的值；同样因为 $[-1, +\infty) \cap \mathbb{R}^*=[-1, 0] \cap (0, +\infty)$ 不为空集，所以存在可以用作输入的值；

经过一番推理后，我们可以确定这个函数的类型为

$$
f: \mathbb{R} \setminus \{-1, 1\} \to \mathbb{R} \setminus \{ 0, -0.5 \}
$$

现在我们构造一个特殊的例子，看看当输出不匹配输入时会发生什么

$$
f(x)= \log(-\exp(x))
$$

1. 首先 $\exp$ 的值变换为 $\mathbb{R} \to \mathbb{R}^+$
2. 然后 $-$ 的输入接上 $\exp$ 的输出，值变换为 $\mathbb{R}^+ \to \mathbb{R}^-$
3. 最后 $\log$ 的输入接上 $-$ 的输出 $\mathbb{R}^-$，但 $\log$ 只定义在 $\mathbb{R}^+$ 上，且 $\mathbb{R}^+ \cap \mathbb{R}^- = \empty$

最后我们发现，任何 $x \in \mathbb{R}$ 都无法作为 $f$ 的输入。因此在实数范围内，这种组合是失败的，我们没有得到新的函数。

在实际编程里，函数类型的推导与之类似。

比如在 TypeScript 中

```ts
const getLength = (s: string): number => s.length;
const isBig = (n: number): boolean => n > 32;
```

分别对应类型

$$
\begin{align*}
  \text{getLength} &: \text{string} \to \text{number} \\
  \text{isBig} &: \text{number} \to \text{boolean}
\end{align*}
$$

如果把 `getLength` 的返回值作为 `isBig` 的参数

```ts
const isLongString = (s) => isBig(getLength(s));
```

由于两者类型都是 `number`，因此可以进行组合，并且能够推断出 `isLongString` 的类型应该为

$$
\text{lengthSquared}: \text{string} \to \text{boolean}
$$

但反过来把 `isBig` 的返回值作为 `getLength` 的参数就存在问题

```ts
const bad = (n) => getLength(isBig(s));
```

这里 `isBig` 的返回值是 `boolean` 而 `getLength` 的参数为 `string`，类型不匹配。因此无法这样组合。

### 函数的复合

函数复合是一种特殊的函数组合，通常用于一组输入和输出可以匹配的函数。

还是先在纯数学中举例。我们有这样一组一元函数

$$
\begin{align*}
  f: A \to B \\
  g: B \to C \\
  h: C \to D \\
\end{align*}
$$

我们希望先计算 $f$，再计算 $g$，最后计算 $h$，即

$$
A \xrightarrow{f} B \xrightarrow{g} C \xrightarrow{h} D
$$

那么这个组合出来的函数需要这样写

$$
h(g(f(x)))
$$

如果再多计算几个函数，这种嵌套会变得非常复杂，难以阅读。数学中用办法简化此时的函数组合，就是函数复合

$$
h \circ g \circ f: A \to D
$$

复合的顺序是从右到左。函数复合是直接对函数进行计算，得到的结果是一个新的函数。在这个函数上输入原来的参数，就可以得到之前组合后的结果

$$
(h \circ g \circ f)(x) = h(g(f(x)))
$$

有部分编程语言可以类似这样简化函数复合的写法。最常见的语法就是管道——几乎就是把函数复合换了个符号，只不过管道的顺序是从左到右，而函数复合是从右到左

$$
h \circ g \circ f \Leftrightarrow f \;|\; g \;|\; h
$$

而最初送入管道的值，通常就放到管道的最左边

$$
x \;|\; f \;|\; g \;|\; h
$$

比如 Bash 的管道

```bash
cat server.log \
  | grep "ERROR" \
  | sort \
  | uniq -c
```

这可以被理解为

```js
uniq_count(sort(grep_error(cat("server.log"))));
```

每个函数（bash 中的术语是命令）的输入是文本，输出也是文本，因此每个函数都是

$$
\text{Text} \to \text{Text}
$$

这满足了函数复合的要求——前一个函数的输出匹配下一个函数的输入。而管道就是把前一个函数的输出作为下一个函数的输入，这就是一种更清晰的、减少函数嵌套的函数复合语法。

再比如 jq 的管道

```jq
.users[]
| select(.age >= 18)
| .name
```

jq 的每个函数都输入 JSON 对象，然后输出 JSON 对象

$$
\text{JSON} \to \text{JSON}
$$

甚至 SQL 也能支持管道语法，比如 GoogleSQL

```sql
FROM users
|> WHERE age >= 18
|> SELECT name, age
|> ORDER BY age DESC
|> LIMIT 10;
```

SQL 的每个函数（SQL 中的术语是操作）都接收表，然后返回表

$$
\text{Table} \to \text{Table}
$$

在正经的函数式语言，比如 Haskell 里，管道更是常见

```haskell
sumSquaresOfEvens :: [Int] -> Int
sumSquaresOfEvens =
    sum
    . map (^2)
    . filter even
```

虽然语法略有不同，但在数学里仍然等价于

$$
\text{sum} \circ \text{map(square)} \circ \text{filter(even)}
$$

这就是正统函数式编程语言的设计：管道从右到左而不是从左到右，完全照搬数学上的函数复合。

JavaScript 目前还没有原生的管道语法，不过可以自己手动实现一个简易的 `pipe`

```js
export function pipe(...fns) {
  return (value) => fns.reduce((value, fn) => fn(value), value);
}
```

这里 `pipe` 本身是一个函数，它的参数是函数，返回值也是函数。这叫做高阶函数——我们马上就会讲到。

`pipe` 返回的函数只有一个参数 `value`。`pipe` 会首先把自身参数中的第一个函数作用在这个 `value` 上，得到的值会被第二个函数作用，然后新的值再被第三个函数作用，一直重复直到最后一个函数作用完成。

`reduce` 会在后续详细介绍。这里只需要知道，`reduce` 有两个参数：第二个参数是初始值，第一个参数是函数。而这个函数的第一个参数是上次计算的结果（未计算时就是初始值），第二个参数是调用 `reduce` 的数组中的一个元素。

## 高阶函数：算子与泛函

我猜你应该在尝试弄懂 `reduce` 各参数的含义时被绕晕了。坏消息是，我们已经介绍完了函数的基本概念，后续的内容都将开始变得抽象。而好消息是，如果逐渐地深入，那么理解这些概念其实并不困难。我相信当你真正体会到函数式编程中那些数学理论的美妙时，也会无可救药地为之着迷。

设函数空间为 $B^A=\{f\mid f:A\to B\}$。

### 算子 Operator

输入函数，输出函数：

$$
T:B^A\to D^C
$$

例如微分算子：

$$
D(f)=f'
$$

即

$$
D:C^1(\mathbb R)\to C(\mathbb R)
$$

程序中的高阶函数：

```js
const transform = f => x => ...
```

与这种结构最接近。

### 泛函 Functional

输入函数，输出一个标量：

$$
L:B^A\to \mathbb R
$$

例如：

$$
L(f)=\int_0^1 f(x)\,dx
$$

或求值泛函：

$$
E_a(f)=f(a)
$$

因此：

> 算子通常是“函数 → 函数”；泛函通常是“函数 → 标量”。

## 2. 闭包 / 参数化函数族

传统数学使用下标表示函数族的参数：

$$
f_a(x)=ax
$$

比如 $\log_a$ 通过修改 $a$ 的值就能得到一系列的对数函数。

但函数式风格更适合直接写成 curried form：

$$
f(a)(x)=ax
$$

或者定义：

$$
f:A\to(B\to C)
$$

于是：

$$
a\mapsto f(a)
$$

其中 $f(a)$ 本身是一个函数：

$$
f(a):B\to C
$$

对应代码：

```js
const f = (a) => (x) => a * x;
```

例如：

```js
const double = f(2);
```

数学上：

$$
f(2)(x)=2x
$$

这种表示对于多个闭包参数尤其清楚：

$$
f(a)(b)(x)=ax+b
$$

对应：

```js
const f = (a) => (b) => (x) => a * x + b;
```

## 3. Currying

函数的输出始终是一个值（数组实际上也只是类型为数组的一个值）。但多元函数需要多个参数，因此在管道里多元函数没办法把自己的输入接到任何函数的输出上。

柯里化目的就是把多元函数变为一元函数，从而更方便放进管道中。

二元函数：

$$
h:A\times B\to C
$$

可以转换为：

$$
\operatorname{curry}(h):A\to(B\to C)
$$

具体定义：

$$
\operatorname{curry}(h)(a)(b)=h(a,b)
$$

反方向：

$$
\operatorname{uncurry}(f)(a,b)=f(a)(b)
$$

因此存在自然对应：

$$
\operatorname{Hom}(A\times B,C)
\cong
\operatorname{Hom}(A,C^B)
$$

代码：

```js
const h = (a, b) => ...
```

柯里化为：

```js
const h = a => b => ...
```

## 4. 函数组合与 Pipe

数学中的函数复合：

$$
g\circ f:A\to C
$$

定义：

$$
(g\circ f)(x)=g(f(x))
$$

程序中的：

```js
pipe(f, g, h)(x);
```

对应：

$$
h\circ g\circ f
$$

函数复合满足：

### 结合律

$$
h\circ(g\circ f)
=
(h\circ g)\circ f
$$

### 恒等函数

存在：

$$
\operatorname{id}_A:A\to A
$$

使：

$$
f\circ\operatorname{id}
=
\operatorname{id}\circ f
=
f
$$

这两个性质是后续范畴论结构的基础。

## 5. `map` 与 Functor

JavaScript：

```js
xs.map(f);
```

只是 API 设计成了 method：

```text
Array object → .map(...)
```

它与 JavaScript 的：

```js
new Map();
```

毫无理论关系。

`Map` 是键值容器；`Array.prototype.map` 中的 `map` 才对应函数式编程中的 mapping。

完全可以把它改写成独立函数：

```js
const map = (f) => (xs) => xs.map(f);
```

于是：

```js
map(f)(xs);
```

更接近数学表示。

## 6. Functor 的数学定义

给定两个范畴：

$$
\mathcal C,\mathcal D
$$

一个函子：

$$
F:\mathcal C\to\mathcal D
$$

包含两部分。

### 对对象的映射

$$
A\mapsto F(A)
$$

### 对态射的映射

若：

$$
f:A\to B
$$

则：

$$
F(f):F(A)\to F(B)
$$

并且必须满足两个定律。

### 保持恒等态射

$$
F(\operatorname{id}_A)
=
\operatorname{id}_{F(A)}
$$

### 保持复合

$$
F(g\circ f)
=
F(g)\circ F(f)
$$

---

### List / Array 作为例子

对象：

$$
A\mapsto List(A)
$$

函数：

$$
f:A\to B
$$

被提升成：

$$
List(f):List(A)\to List(B)
$$

其中：

$$
List(f)([a_1,\ldots,a_n])
=
[f(a_1),\ldots,f(a_n)]
$$

JavaScript 中就是：

```js
xs.map(f);
```

因此 `map` 的核心作用可以概括为：

$$
(A\to B)
\longmapsto
(F(A)\to F(B))
$$

同时保持恒等与复合。

## 7. `reduce` 比 Monoid 更一般

JavaScript：

```js
xs.reduce(f, initial);
```

并不要求 `initial` 是单位元。

一般来说：

$$
\operatorname{foldl}:
(A\times B\to A)
\to
A
\to
List(B)
\to
A
$$

也就是：

- $A$：累积器类型
- $B$：元素类型
- $A\times B\to A$：每一步如何更新累积器
- 初始值只需要属于 $A$

例如：

```js
users.reduce(
  (acc, user) => ({
    ...acc,
    [user.id]: user,
  }),
  {},
);
```

这并不是简单的幺半群折叠。

### Monoid 只是一个特殊情况

如果：

$$
(A,\star,e)
$$

满足：

$$
(a\star b)\star c
=
a\star(b\star c)
$$

且：

$$
e\star a=a\star e=a
$$

那么可以：

$$
\operatorname{reduce}(\star,e)
$$

例如求和：

$$
(\mathbb Z,+,0)
$$

所以：

> Monoid 能自然地产生一种 `reduce`，但 `reduce` 本身不要求 Monoid。

## 8. Option / Result：扩展陪域

若：

$$
f:A\rightharpoonup B
$$

只是一个部分函数，例如：

$$
f(x)=\frac1x
$$

在 $x=0$ 时没有定义。

可以把它改成 total function：

$$
\hat f:A\to B\cup\{\mathrm{Failure}\}
$$

前提是：

$$
\mathrm{Failure}\notin B
$$

更严格地，为避免元素碰撞，常写成不交并：

$$
B\sqcup\{\mathrm{Failure}\}
$$

或者类型论中常写：

$$
B+E
$$

这里的 $+$ 不是普通数值加法，而是 **coproduct / sum type**。

程序中：

```text
Option<B>
Result<B, E>
```

正是在做这件事。

## 9. Monad 与错误传播

假设：

$$
f:A\to Result(B,E)
$$

$$
g:B\to Result(C,E)
$$

普通复合：

$$
g\circ f
$$

无法成立，因为 $f$ 的输出不是 $B$。

Monad 提供一种组合操作，通常称为：

$$
\operatorname{bind}
$$

类型：

$$
Result(A,E)
\to
(A\to Result(B,E))
\to
Result(B,E)
$$

于是：

$$
A\to Result(B,E)
$$

与：

$$
B\to Result(C,E)
$$

可以进行 Kleisli composition：

$$
g\star f:
A\to Result(C,E)
$$

---

### 不会产生“error drilling”吗？

如果手写：

```js
const r = f(x);

if (!r.ok) return r;

return g(r.value);
```

确实会产生大量样板代码。

因此实际函数式 API 会把这段逻辑封装进：

```js
result.flatMap(g);
```

或：

```js
bind(result, g);
```

从而写成：

```js
parse(input).flatMap(validate).flatMap(calculate).flatMap(format);
```

错误传播由 `flatMap/bind` 自动处理。

不同语言进一步提供语法糖：

```text
Haskell        do notation
Scala          for-comprehension
Rust           ?
Elixir         with
JavaScript     Promise.then / async-await
```

所以 Monad 的意义之一正是：

> 把“传播上下文”的样板逻辑从每个业务函数中抽离出来。

## 10. 递归与不动点

不能直接写：

$$
F(n)=nF(n-1)
$$

来解释“不动点”，因为这里的 $F$ 已经是最终递归函数本身。

要讨论不动点，必须再高一阶。

定义一个**作用于函数的算子**：

$$
\Phi:(\mathbb N\to\mathbb N)
\to
(\mathbb N\to\mathbb N)
$$

定义：

$$
\Phi(g)(n)
=
\begin{cases}
1,&n=0\\
n\,g(n-1),&n>0
\end{cases}
$$

注意：

- $g$ 是输入函数；
- $\Phi(g)$ 是输出函数；
- 此时没有递归调用 $\Phi$。

现在寻找一个函数 $f$，满足：

$$
\Phi(f)=f
$$

这样的 $f$ 就是 $\Phi$ 的不动点。

代入：

$$
f(n)
=
\begin{cases}
1,&n=0\\
n\,f(n-1),&n>0
\end{cases}
$$

于是：

$$
f(n)=n!
$$

因此 factorial 可以理解为：

$$
\boxed{f=\operatorname{fix}(\Phi)}
$$

其中 fixed-point operator 满足：

$$
\operatorname{fix}(\Phi)
=
\Phi(\operatorname{fix}(\Phi))
$$

Lambda Calculus 中的 $Y$ combinator 就满足类似关系：

$$
Y(\Phi)=\Phi(Y(\Phi))
$$

关键区别：

$$
\Phi
$$

是“函数 → 函数”的高阶算子；

$$
f
$$

才是真正的递归函数。

---

## 总体对应

| 函数式编程            | 数学结构                            |
| --------------------- | ----------------------------------- |
| pure function         | 映射 $A\to B$                       |
| higher-order function | 函数空间上的映射                    |
| operator              | 函数 $\to$ 函数                     |
| functional            | 函数 $\to$ 标量                     |
| closure               | $A\to(B\to C)$ / 参数化函数族       |
| currying              | $A\times B\to C \cong A\to(B\to C)$ |
| composition / pipe    | 函数复合                            |
| map                   | 函子的态射映射                      |
| Functor               | 保持恒等与复合的范畴间映射          |
| reduce / fold         | 代数上的折叠                        |
| monoid reduction      | fold 的重要特殊情况                 |
| Option / Result       | 扩展陪域 / sum type                 |
| bind / flatMap        | Kleisli composition                 |
| recursion             | 高阶算子的不动点                    |

函数式编程最值得把握的一条主线是：

$$
\boxed{
\text{值}
\rightarrow
\text{函数}
\rightarrow
\text{函数之间的组合}
\rightarrow
\text{保持组合的结构}
}
$$

所以 FP 最深层的魅力并不只是“函数是一等公民”，而是：

$$
\boxed{\text{程序逐渐变成一个可以用代数规律推理的对象}}
$$

这也是它与数学之间最根本的联系。
